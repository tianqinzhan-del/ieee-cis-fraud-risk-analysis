# IEEE-CIS 支付交易欺诈风险分析

基于 IEEE-CIS Fraud Detection 数据集，评估支付交易反欺诈规则的业务效果。
项目不追求模型精度，而是回答风控策略落地时最实际的问题：

> **在每天固定人工审核名额的约束下，应该把哪些交易送进审核队列？**

## 核心结论

| 结论 | 结果 |
| --- | --- |
| 整体欺诈率 | 3.50%（20,663 / 590,540） |
| 最强风险群体 | 产品 C + 信用卡：欺诈率 16.92%，提升 4.84 倍，贡献 22.57% 的欺诈交易 |
| 单条金额规则 | 金额 > 500：命中率 4.41%，召回率 4.88%，仅略高于整体欺诈率 |
| 排序策略对比 | 测试期每天 100 个名额：风险分排序召回 21.63%，金额排序 5.76% |
| 三档策略 | A 激进方案总召回 29.08%，日均拒绝 51.00 笔，日均误拒 38.24 笔 |

## 数据

[IEEE-CIS Fraud Detection](https://www.kaggle.com/c/ieee-fraud-detection) 竞赛数据：

- `train_transaction.csv`：590,540 行 × 394 列
- `train_identity.csv`：144,233 行 × 41 列

将两个文件放入 `data/` 目录。数据文件不随仓库提交。
也可通过环境变量 `FRAUD_DATA_DIR` 指向其他数据目录。

## 方法

1. **数据概览**：规模、标签分布、时间跨度、字段缺失率。
2. **金额规则敏感性**：5 个阈值下送审量、召回率、命中率、误伤量的变化。
3. **多维风险画像**：按产品、卡组织、卡类型、产品 × 卡类型、邮箱域名分组，
   同时看交易量、欺诈率、提升倍数、欺诈占比四个指标。
4. **identity 表连接**：校验主键唯一性与连接前后行数，比较有无身份信息的欺诈率差异。
5. **时间切分**：按天划分训练期（1–109）、验证期（110–145）、测试期（146–182），
   避免用未来信息调参。
6. **查表打分**：以训练期历史欺诈率作为风险分，采用三级回退
   （产品 + 卡类型 + 邮箱 → 产品 + 卡类型 → 全局欺诈率）。
7. **容量与策略评估**：容量曲线、固定分数分档、三档处置方案、7 天稳定性检查。

## 运行

```bash
pip install -r requirements.txt
python run_analysis.py
```

运行后生成：

- `outputs/report.md`：完整分析报告
- `outputs/tables/*.csv`：各环节明细表

Notebook 形式：

```bash
pip install -r requirements-dev.txt
jupyter lab notebooks/01_analysis.ipynb
```

## 设计说明

- **按时间切分，不随机切分**：线上场景只能使用过去的数据制定规则，
  随机切分会让未来信息泄漏到训练期。
- **打分器只在训练期拟合**：验证期用于比较策略，测试期只做最终评估。
- **所有效果指标都附带送审量**：只报告召回率会掩盖审核成本，
  风控规则必须在成本与收益之间取舍。
- **小样本分组不进入结论**：风险画像要求分组交易量不低于 1,000 笔，
  避免“几笔交易撑起高欺诈率”的统计噪声。
